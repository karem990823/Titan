# 1. RESTRICCIONES REGULATORIAS Y DE CUMPLIMIENTO
## REST-REG-001: No integración con el Ministerio de Trabajo
**Categoría:** Legal – Obligatoria

**Descripción:** Por normatividad, los instructores deben validar manualmente la información en un plazo de 5 días hábiles antes de reportarla al Ministerio de Trabajo. Por esta razón, el sistema no puede enviar datos automáticamente.

**Implicaciones:**
- El sistema debe ofrecer exportación manual de archivos.
- No se puede implementar API o sincronización automática.
- Se deben evitar cargas automáticas que omitan la validación humana.

**Impacto:** CRÍTICO

**Flexibilidad:** NULA

---

## REST-REG-002: Cumplimiento de normativas NTI y resoluciones
**Categoría:** Legal – Obligatoria

**Descripción:** Los datos almacenados y los certificados generados deben cumplir estrictamente con la NTI y las resoluciones del Ministerio de Trabajo.

**Implicaciones:**
- Todos los certificados deben incluir la información exigida por la normativa.
- El sistema debe almacenar historial de cursos para auditorías.
- Los datos deben mantenerse íntegros y verificables.

**Impacto:** CRÍTICO

**Flexibilidad:** BAJA

---

## REST-REG-003: Protección de datos personales (Ley 1581)
**Categoría:** Legal – Obligatoria

**Descripción:** El sistema debe garantizar el manejo seguro, ético y autorizado de todos los datos personales de instructores y participantes.

**Implicaciones:**
- Deben existir mecanismos de consentimiento informado.
- Se requiere tratamiento seguro de datos sensibles.
- Se deben habilitar medios para corrección o actualización de datos.

**Impacto:** CRÍTICO

**Flexibilidad:** NULA

---

**Categoría:** Plataforma – Definida

**Implicaciones:**

- Requiere conexión a internet para su uso.

## REST-TEC-002: Sin restricción de stack tecnológico

**Descripción:** El cliente permite libertad total en la elección de tecnologías.

**Implicaciones:**

**Flexibilidad:** ALTA

## REST-TEC-003: Tiempo máximo de búsqueda por CC (5–6 segundos)
**Categoría:** Rendimiento – Obligatoria

# 4. RESTRICCIONES DE SEGURIDAD
## REST-SEG-001: Autenticación robusta para personal interno
**Categoría:** Seguridad - Obligatoria

**Descripción:** La empresa requiere un sistema "super privado" con fuerte control de accesos.

**Implicaciones:**
- Se deben usar contraseñas seguras.
- Posibilidad futura de implementar MFA.
- Roles bien diferenciados.

**Impacto:** CRÍTICO

**Flexibilidad:** MEDIA

---

## REST-SEG-002: Participantes solo pueden descargar su certificado
**Categoría:** Seguridad – Obligatoria

**Descripción:** Los participantes no deben acceder a ninguna otra información del sistema.

**Implicaciones:**
- Vista limitada a una sola funcionalidad.
- Validación obligatoria de identidad por número de documento.
- Sin acceso a datos de terceros.

**Impacto:** CRÍTICO

**Flexibilidad:** NULA

---

## REST-SEG-003: Información administrativa altamente sensible
**Categoría:** Seguridad – Obligatoria

**Descripción:** Los datos internos requieren protección especial.

**Implicaciones:**
- Implementar cifrado en base de datos.
- Accesos restringidos por rol.
- Políticas de manejo seguro de información.

**Impacto:** ALTO

**Flexibilidad:** BAJA

---

## REST-SEG-004: Sistema de auditoría obligatorio
**Categoría:** Seguridad - Obligatoria
**Descripción:** Debe registrarse toda acción importante realizada por usuarios internos.

**Implicaciones:**

- Auditorías deben poder exportarse.

**Flexibilidad:** MEDIA

### REST-USU-002: Soporte de Navegadores Modernos
**Categoría:** Compatibilidad - Definida

- Mejor performance y experiencia de desarrollo

**Impacto:** MEDIO  
**Flexibilidad:** MEDIA - Puede ajustarse según analítica

---

### REST-USU-003: Conexiones 4G Estándar Colombianas
**Categoría:** Experiencia de Usuario - Definida  
**Descripción:** El sistema debe funcionar óptimamente con conexiones 4G estándar en Colombia (aproximadamente 10 Mbps), no se puede asumir 5G o WiFi de alta velocidad.

**Implicaciones:**
- Optimización agresiva de tamaño de assets
- Compresión de imágenes y videos
- Lazy loading de contenido no crítico
- Progressive Web App para menor uso de datos
- Modo offline para funcionalidades básicas

**Fuente:** RNF-001.1 / Contexto Colombia  
**Impacto:** ALTO  
**Flexibilidad:** NULA - Realidad del mercado
